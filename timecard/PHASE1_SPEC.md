# フェーズ1 実装仕様書

対象: 温井ダムリゾート 勤怠打刻システム
前提: `timecard/DESIGN.md` を先に読むこと。この文書は設計を実装レベルに落としたもの。

**このフェーズのゴール: カードをかざすと打刻され、スプレッドシートに記録が残る。**
丸め・集計・シフト連携はフェーズ2以降なので、ここでは実装しない。

---

## 0. 実装の進め方

Google Apps Script プロジェクトとして作る。ローカルには GAS のソースをそのまま置き、`clasp` で反映するか、内容をコピーして GAS エディタに貼る。

```
timecard/
├── DESIGN.md          設計書（既存）
├── PHASE1_SPEC.md     この文書
└── gas/
    ├── appsscript.json
    ├── Code.gs          エントリポイント（doGet / doPost / ルーティング）
    ├── Punch.gs         打刻ロジック
    ├── Staff.gs         スタッフ名簿・QRトークン
    ├── Device.gs        端末バインド
    ├── Admin.gs         管理画面用の処理
    ├── Setup.gs         初期セットアップ（シート自動生成・名簿投入）
    ├── Util.gs          共通処理（日時・ハッシュ・ログ）
    ├── punch.html       打刻画面
    ├── device.html      端末登録画面
    ├── admin.html       管理画面
    └── styles.html      共通CSS（HtmlService の include で読む）
```

**API 呼び出しは `google.script.run` に統一し、呼び出し部分を1箇所にまとめること。**
将来フロントを外部ホスティングへ移す可能性があるため（DESIGN.md 5.5）、通信部分が散らばっていると移行できなくなる。

## 1. スプレッドシートの構成

勤怠専用 Google アカウントのドライブに、スプレッドシート **`温井ダムリゾート_勤怠`** を1つ作る。
`Setup.gs` に、以下のシートとヘッダーを自動生成する関数 `initSpreadsheet()` を用意すること（手作業でシートを作らせない）。

### シート `スタッフ`

| 列 | 名前 | 内容 |
|---|---|---|
| A | 社員ID | `S001` 形式。自動採番 |
| B | 氏名 | **フルネーム。これが正**（例: 橋本　潤一郎） |
| C | シフト表表記 | シフト表側の表記（例: 橋本、ひかる） |
| D | 区分 | `社員` / `パート` / `臨時` |
| E | QRトークン | `wnm_` + 32桁hex。**推測不可能な値** |
| F | みなし残業時間 | 社員=40、パート=0（フェーズ3で使用） |
| G | 在籍 | `TRUE` / `FALSE` |
| H | 表示順 | 打刻画面の名前ボタンの並び順 |
| I | 登録日時 | |
| J | 備考 | |

初期データは DESIGN.md 1.5 の名簿12名を投入する。区分は下記のとおり。

| 氏名 | 区分 |
|---|---|
| 橋本　潤一郎 / 三滝　啓人 / 三村　諒 / 沖田　勝克 | 社員 |
| 上記以外の8名 | パート |

> 区分は暫定。実際の雇用形態と違う場合は名簿シート上で直せばよい。

### シート `打刻ログ`（追記専用。編集させない）

| 列 | 名前 | 内容 |
|---|---|---|
| A | ログID | UUID |
| B | 打刻日時 | `yyyy-MM-dd HH:mm:ss`。**サーバー時刻を使う**（端末時刻は信用しない） |
| C | 営業日 | `yyyy-MM-dd`。打刻日時から算出（夜勤なしのため暦日と一致） |
| D | 社員ID | |
| E | 氏名 | 打刻時点のフルネーム |
| F | 種別 | `出勤` / `退勤` |
| G | 端末ID | どの端末から打刻されたか |
| H | 入力方法 | `QR` / `名前ボタン` / `管理者代理` |
| I | 備考 | |

**このシートは上書き・削除をしない。**修正はフェーズ2で別シートに追記する形で行う。

### シート `端末`

| 列 | 名前 | 内容 |
|---|---|---|
| A | 端末ID | UUID |
| B | 端末名 | 管理者が付ける名前（例: フロントiPad） |
| C | 端末トークン | ランダム64桁。**この値の一致だけが打刻の可否を決める** |
| D | 登録日時 | |
| E | 最終利用日時 | |
| F | 有効 | `TRUE` / `FALSE`。失効させたら `FALSE` |

### シート `臨時割当`

スポットの方に予備カードを割り当てる（DESIGN.md 4.6）。

| 列 | 名前 | 内容 |
|---|---|---|
| A | 予備カードID | `臨時1`〜`臨時5` |
| B | QRトークン | 予備カードの固定トークン |
| C | 氏名 | 割り当てた方のフルネーム |
| D | 対象日 | `yyyy-MM-dd` |
| E | 登録日時 | |

**翌日以降の割当は自動的に無効**とする（対象日が今日でなければ未割当扱い）。フェーズ1では日次バッチは作らず、参照時に判定するだけでよい。

### シート `設定`

| キー | 既定値 | 内容 |
|---|---|---|
| `管理者パスワードハッシュ` | （初期セットアップ時に設定） | SHA-256。平文で保存しない |
| `通知先メール` | 管理者のアドレス | |
| `名前ボタン方式を有効にする` | `FALSE` | カード忘れ・スキャナ故障時に `TRUE` にする |
| `重複打刻の抑止分数` | `5` | この分数以内の同一人物の再スキャンは無視 |

## 2. 端末バインド（最重要）

### 登録

1. 管理者が `?page=device` を開く
2. 管理者パスワードを入力して送信
3. サーバー側でハッシュを照合。一致したら端末トークンを生成し `端末` シートに追加
4. **クライアントの `localStorage` に端末トークンを保存**
5. 以後、打刻リクエストには必ずこのトークンを付ける

### 検証

**すべての打刻リクエストで、最初に端末トークンを検証する。**

```
punch(qrToken, deviceToken) {
  1. deviceToken が 端末シートにあり、有効 = TRUE か
     → NO なら即座に拒否。「この端末では打刻できません」
  2. 以降の処理へ
}
```

- **端末トークンの検証を通らないリクエストは、いかなる処理も行わない。**
- パスワードは `設定` シートにハッシュで保存し、平文はどこにも残さない。
- 照合はサーバー側（.gs）で行う。クライアントに正解を送らない。

## 3. 打刻の流れ

### 3.1 入力の受け取り

スキャナは Bluetooth HID（キーボード）として動くため、**画面上の隠し入力欄に文字が打ち込まれ、最後に Enter が来る**。

- 画面には常にフォーカスの当たった非表示の input を置く
- Enter（keydown の `Enter`）を検知したら、その時点の文字列を QR トークンとして送信し、入力欄を空にする
- **フォーカスが外れても自動的に戻す**（他をタップされても打刻できなくならないように）
- ソフトウェアキーボードは HID 接続中は出ないが、`readonly` 等で出さない工夫をしておく

### 3.2 出勤 / 退勤の判定

```
当日（営業日）の当該社員の打刻ログを見る
├─ 記録なし          → 出勤
├─ 最後が「出勤」     → 退勤
└─ 最後が「退勤」     → 出勤（同日再出勤。記録は残す）
```

**判定は必ず「当日の」ログだけを見る。**前日の退勤漏れがあっても、翌日の出勤が「退勤」と誤判定されない。

### 3.3 重複の抑止

同一社員の直近の打刻が `重複打刻の抑止分数`（既定5分）以内なら、**新しい記録を作らず**「すでに打刻済みです（9:00 出勤）」と表示する。

### 3.4 応答

サーバーは以下を返す。

```
{
  ok: true,
  name: "橋本　潤一郎",
  type: "出勤",
  time: "9:00",
  greeting: "おはようございます",
  warning: null            // 前日の退勤打刻がない等
}
```

エラー時は `ok: false` と、**スタッフが読んで分かる日本語のメッセージ**を返す（技術用語を出さない）。

| 状況 | メッセージ |
|---|---|
| 端末未登録 | この端末では打刻できません |
| 未登録のカード | このカードは使えません。担当者にお伝えください |
| 5分以内の再スキャン | すでに打刻済みです（9:00 出勤） |
| 通信エラー | 打刻しました（送信待ち） ※後述 |

## 4. 打刻画面（punch.html）

### 待機画面

- 画面上部に**大きな時計**（現在時刻・日付・曜日）。1秒ごとに更新
- 中央に「**カードをかざしてください**」
- `名前ボタン方式を有効にする` が `TRUE` のときだけ、下部に名前ボタンを表示

### 結果画面

```
┌──────────────────────────────┐
│      橋本　潤一郎 さん        │  ← 72px 太字
│      おはようございます        │  ← 48px
│  ✅ 出勤 9:00 打刻しました     │  ← 96px。出勤=青 / 退勤=橙
└──────────────────────────────┘
```

- **5秒後に自動で待機画面へ戻る**
- 成功音を鳴らす（Web Audio API。音声ファイルを外部から読まない）
- **音声で読み上げる**（Web Speech API / `SpeechSynthesisUtterance`、`lang: 'ja-JP'`）
  例: 「はしもとさん、しゅっきん、くじ」
  読み上げに失敗しても打刻は成立させる（`try/catch` で握りつぶす）
- 警告がある場合は結果の下に表示し、この時だけ 10 秒表示する

### オフライン対応

- 送信に失敗したら `localStorage` のキューに積み、「打刻しました（送信待ち）」と表示する
- 30秒ごとに再送を試みる。成功したらキューから消す
- **スタッフを不安にさせないことを優先する。**打刻が失われないことが担保できていれば、その場で成功と伝えてよい
- キューに残ったまま24時間経過したものは管理画面に警告として出す

### 表示の要件

- 文字は特大。iPad を離れて見ても読める大きさ
- 色でも区別（出勤=青、退勤=橙、エラー=赤）
- タップできる要素を待機画面に置かない（誤操作防止）

## 5. 管理画面（admin.html）

パスワードで保護する（端末登録と同じ管理者パスワード）。フェーズ1では以下だけ。

### スタッフ管理
- 一覧表示・追加・編集・在籍のON/OFF
- **QRトークンの発行 / 再発行**（再発行すると旧カードは即無効）
- **QRカードの印刷用ページ**を生成する
  - 名刺サイズ、1枚に QR + **フルネームを大きく**
  - QR は外部 API を使わず、**ライブラリをGASプロジェクト内に持つか、印刷ページ内でJSで生成**する
    （外部の QR 生成 API に氏名やトークンを送らないこと）

### 臨時割当
- 予備カード `臨時1`〜`臨時5` に、氏名と対象日を割り当てる
- 氏名の入力だけで登録できること（10秒で終わる操作にする）

### 端末管理
- 登録済み端末の一覧、失効（有効=FALSE）

## 6. セキュリティ要件（実装時に必ず守る）

- **端末トークンの検証を通らない打刻リクエストは、いかなる処理もしない**
- 管理者パスワードは **SHA-256 でハッシュ化**して保存。平文をシートにもコードにも書かない
- QR トークン・端末トークンは `Utilities.getUuid()` などで生成し、**連番や氏名から導出しない**
- 打刻ログは**追記のみ**。フェーズ1では更新・削除の関数を作らない
- QR コード生成で**外部サービスに氏名やトークンを送らない**
- Web アプリの公開設定
  - 打刻画面: 「実行するユーザー: 自分」「アクセスできるユーザー: 全員」
    → スタッフに Google ログインをさせないため。**安全性は端末バインドで担保する**
- `設定` シートと `端末` シートは管理者以外が見る必要がないため、スプレッドシート自体の共有を管理者に限定する

## 7. 完了の判定

以下がすべて動けばフェーズ1は完了。

- [ ] `initSpreadsheet()` を実行すると、必要なシートとヘッダーと名簿12名が作られる
- [ ] 管理画面から QR カードを発行し、印刷用ページが出る
- [ ] 端末登録画面で管理者パスワードを入れると、その端末で打刻できるようになる
- [ ] **登録していない端末（PC のブラウザ等）から開くと打刻できない**
- [ ] カードをかざすと、フルネームと「出勤 HH:mm」が全画面で出て、音が鳴り、読み上げられる
- [ ] もう一度かざすと「すでに打刻済みです」と出る（5分以内）
- [ ] 5分以上あけてかざすと「退勤」になる
- [ ] `打刻ログ` シートに、日時・氏名・種別・端末ID が記録されている
- [ ] 機内モードにして打刻すると「送信待ち」と出て、復帰後に自動送信される
- [ ] 未登録のカードをかざすと「このカードは使えません」と出る

### 動作確認の順序

1. `initSpreadsheet()` を実行
2. Web アプリをデプロイして URL を取得
3. PC のブラウザで打刻画面を開く → **打刻できないことを確認**（ここが一番大事）
4. 端末登録 → 打刻できるようになることを確認
5. QR カードを印刷（テストは画面に表示した QR をスキャナで読ませてもよい）
6. 上記チェックリストを順に確認

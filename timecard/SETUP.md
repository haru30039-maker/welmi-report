# セットアップ手順書（勤怠専用 Google アカウントでの作業）

この文書は、**コードができたあとに管理者がブラウザで行う作業**をまとめたもの。
順番どおりに進めれば打刻画面が使えるようになる。

---

## 0. いつやるか

| タイミング | やること | Google ログイン |
|---|---|---|
| **今（設計・実装中）** | Claude がコードを書く | **不要** |
| **フェーズ1のコードが完成したら** | この手順書に沿ってセットアップ | **ここで初めて必要** |
| 日々の運用 | iPad で打刻するだけ | **スタッフは一切不要** |

**重要**: Claude は勤怠専用アカウントにログインできない（できてはいけない）。コードは Claude が作り、**Google 上での作業は管理者が行う**という分担になる。所要時間は 30〜60分程度。

---

## 1. 事前準備：ブラウザを分ける（最初にやること）

**普段使いの Google アカウントと同時にログインした状態で作業しない。**

複数アカウントにログインしていると、Apps Script が意図しないアカウントで作成・実行されることがある。これが起きると、勤怠データが共有アカウント側に作られてしまい、当初避けたかった「全社員に見える」状態になりかねない。

対策（どちらでもよい）:

| 方法 | 手順 |
|---|---|
| **Chrome のプロファイルを分ける（推奨）** | Chrome 右上のアイコン → 「追加」→ 勤怠専用アカウントでログイン。以後この専用ウィンドウでのみ作業する |
| シークレットウィンドウを使う | 毎回ログインし直す必要があるが、混ざる心配はない |

---

## 2. スプレッドシートを作る

1. 勤怠専用アカウントで Google ドライブを開く
2. 新規 → Google スプレッドシート
3. ファイル名を **`温井ダムリゾート_勤怠`** にする
4. **共有はしない**（自分だけが見られる状態のままにする）

> シート（タブ）は手で作らなくてよい。あとで `initSpreadsheet()` を実行すると、必要なシートとヘッダーと名簿12名が自動で作られる。

---

## 3. Apps Script にコードを入れる

スプレッドシートのメニューから **拡張機能 → Apps Script** を開く。

方法は2つある。

### 方法A: 画面にコピー＆ペースト（スマホ／すぐ試したい場合）

1. Apps Script エディタの左側「ファイル」の＋から、ファイルを1つずつ追加する
2. `.gs` ファイルはスクリプト、`.html` ファイルは HTML として追加する
3. リポジトリの `timecard/gas/` の中身をそれぞれ貼り付ける
4. 保存

ファイル数が10個ほどあるので手間はかかるが、確実で追加のインストールが要らない。

### 方法B: clasp を使う（Mac に移ってからなら、こちらが楽）

```bash
npm install -g @google/clasp
clasp login                    # ブラウザが開くので勤怠専用アカウントでログイン
cd timecard/gas
clasp push                     # コードがまとめて反映される
```

初回のみ `clasp create` またはスクリプトIDの紐づけが必要。**以後の修正は `clasp push` だけで反映できる**ので、フェーズ2以降を考えると Mac に移ったタイミングでこちらへ切り替えるのがよい。

---

## 4. 初回実行と権限の承認

1. Apps Script エディタで、実行する関数に **`initSpreadsheet`** を選び「実行」
2. **「承認が必要です」**と出るので「権限を確認」
3. アカウントを選ぶ（**勤怠専用アカウントであることを必ず確認**）
4. **「このアプリは Google で確認されていません」という警告が出る** ← これは正常
   - 自分で作ったスクリプトなので必ず表示される。異常ではない
   - 左下の **「詳細」** をクリック → **「（プロジェクト名）に移動（安全ではないページ）」** をクリック
5. 「許可」を押す
6. 実行が完了したら、スプレッドシートに戻る

**確認**: `スタッフ` `打刻ログ` `端末` `臨時割当` `設定` のシートができ、名簿12名が入っていればOK。

> ここでつまずく人が多いのは手順4の警告。「危ないのでは」と止まってしまいがちだが、**自作スクリプトでは必ず出るもの**で、Google の審査を受けていないという意味でしかない。

---

## 5. ウェブアプリとしてデプロイする

**ここの設定を間違えると、打刻できない／データが誰にでも見えるという事故になる。慎重に。**

1. Apps Script エディタ右上の **「デプロイ」→「新しいデプロイ」**
2. 歯車アイコン → 種類として **「ウェブアプリ」** を選ぶ
3. 設定を以下のとおりにする

| 項目 | 設定値 | 理由 |
|---|---|---|
| 説明 | `勤怠打刻 v1` など | あとで見分けるため |
| **次のユーザーとして実行** | **自分（勤怠専用アカウント）** | スプレッドシートへの書き込み権限がこのアカウントのものになる |
| **アクセスできるユーザー** | **全員** | **スタッフに Google ログインをさせないため。安全性は端末バインドで担保する** |

4. デプロイ → **ウェブアプリの URL が表示されるのでコピーして保管する**

> 「アクセスできるユーザー: 全員」に不安を感じるかもしれないが、これは正しい設定。URL を知っていても**登録された端末以外からは打刻できない**仕組みになっている（DESIGN.md 3章）。逆にここを「自分のみ」にすると、スタッフが Google ログインを求められて運用が成立しない。

### 修正したとき

コードを直したら **「デプロイ」→「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」→ デプロイ** とする。
**「新しいデプロイ」を選ぶと URL が変わってしまう**ので注意（iPad の設定をやり直すことになる）。

---

## 6. 管理者パスワードを設定する

1. デプロイした URL の末尾に `?page=admin` を付けて開く
2. 初回はパスワードの設定を求められるので、**管理者だけが知るパスワード**を設定する
3. このパスワードは端末登録にも使う

> パスワードはスプレッドシートにハッシュ化して保存される。平文はどこにも残らないので、忘れると再設定が必要になる。パスワード管理アプリなどに控えておくこと。

---

## 7. iPad 側の作業

**iPad に Google アカウントでログインする必要はない。**（ここが重要。スタッフに一切ログインさせない設計）

1. iPad の Safari でデプロイした URL を開く
2. 共有ボタン → **「ホーム画面に追加」**。名前は「打刻」など分かりやすく
3. アイコンを1ページ目の左上に置く
4. URL の末尾に `?page=device` を付けて開き、**管理者パスワードを入力して端末を登録する**
5. 打刻画面に戻り、**打刻できるようになっていることを確認**

### iPad の設定

- 設定 → 画面表示と明るさ → 自動ロック → **なし**
- 電源に挿しっぱなしにする
- 設定 → スクリーンタイム → コンテンツとプライバシーの制限 → コンテンツ制限 → Web コンテンツ → **「許可されたWebサイトのみ」**
  - 打刻システムの URL とチェックインシステムの URL を登録する
  - **スクリーンタイム用パスコードはスタッフに教えない**

### スキャナのペアリング

1. Tera HW0002 を **HID（キーボード）モード**に設定する（付属の日本語説明書にある設定用QRを読ませる）
2. iPad の 設定 → Bluetooth からペアリングする
3. **自動検知スキャンモード**に設定し、スタンドに設置する

## 8. 動作確認（この順番で）

| # | 確認すること | 期待する結果 |
|---|---|---|
| 1 | **PC のブラウザで打刻画面を開く** | **「この端末では打刻できません」と出る** ← 最重要 |
| 2 | iPad で打刻画面を開く | 大きな時計と「カードをかざしてください」が出る |
| 3 | カードをかざす | フルネームと「出勤 HH:mm」が全画面で出て、音が鳴り、読み上げられる |
| 4 | すぐもう一度かざす | 「すでに打刻済みです」と出る |
| 5 | 5分以上あけてかざす | 「退勤」になる |
| 6 | スプレッドシートの `打刻ログ` を見る | 日時・氏名・種別・端末IDが記録されている |
| 7 | 機内モードにして打刻 | 「打刻しました（送信待ち）」と出て、復帰後に自動送信される |
| 8 | 未登録のカードをかざす | 「このカードは使えません」と出る |

**1番から始めること。**不正防止が効いているかが今回の肝なので、そこが確認できていれば残りは調整の話になる。

## 9. アカウントの安全対策

勤怠データ（＝給与が推測できる情報）が入るため、以下を設定しておく。

- **2段階認証を有効にする**（勤怠専用アカウントの設定 → セキュリティ）
- パスワードは他のサービスと使い回さない
- ログイン情報を知るのは管理者のみに限る
- 復旧用のメールアドレス・電話番号を設定しておく（ログインできなくなると勤怠データにアクセスできなくなる）

## 10. つまずきやすいところ

| 症状 | 原因と対処 |
|---|---|
| 「このアプリは確認されていません」で止まる | 正常。「詳細」→「（プロジェクト名）に移動」で進む（手順4） |
| 別のアカウントでスクリプトが作られた | 複数ログイン状態が原因。Chrome のプロファイルを分けてやり直す（手順1） |
| コードを直したのに反映されない | デプロイを更新していない。「デプロイを管理」→ 鉛筆 →「新バージョン」（手順5） |
| 修正後に URL が変わった | 「新しいデプロイ」を選んでしまった。「デプロイを管理」から既存のものを更新する |
| iPad で打刻できない | 端末登録がまだ。`?page=device` から登録する（手順7-4） |
| localStorage が消えて打刻できなくなった | Safari の履歴消去などが原因。`?page=device` から再登録すれば1分で復旧する |
| スキャナが反応しない | HID モードになっていない／Bluetooth が切れている。ペアリングし直す |
